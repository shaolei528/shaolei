# 《深海搭档 / Deep Sea Duo》两台手机真实联机验收流程

当前正式联机方式是 **6 位房间码自动配对**。正常玩家不需要来回复制 WebRTC Offer / Answer 长文本。

当前网络设计：

1. Deep Sea Duo 页面和 6 位房间码 API 都由它自己的 Netlify 项目提供；
2. 页面调用同域 `/room` 完成 Offer / Answer 交换；
3. 真正游戏数据通过同一 Wi‑Fi / 热点上的 WebRTC DataChannel 点对点传输；
4. 房主仍然是唯一权威模拟。

这套链路不使用《ABYSSAL WAKE》的 Cloudflare Worker，也不依赖 Supabase 作为正常配对入口。

## 0. 测试前准备

准备两台手机：

- **手机 A：房主（Host）**
- **手机 B：加入者（Guest）**

推荐：iPhone / iPad 用 Safari，Android 用 Chrome。两台手机都横屏。

## 1. 网络

推荐两台手机连接同一个 Wi‑Fi，或手机 A 开热点、手机 B 连接 A 的热点。

6 位房间码需要短暂访问 Netlify `/room`；建立 WebRTC 后，移动、攻击、怪物、Boss 等实时游戏 packet 不经过这个房间 API。

测试时建议关闭 VPN / 代理 / iCloud Private Relay，减少额外网络变量。

## 2. 打开同一个 HTTPS 版本

两台手机都打开正式 `deep-sea-duo.netlify.app` 地址，并确认页面底部 build 标识一致。

当前 Netlify 同源版本标识应为：

`NET-N1`

## 3. 手机 A 创建房间

1. 点 **创建房间**。
2. 页面先显示一个真正的 **6 位数字**。
3. 把这 6 位数字告诉朋友。
4. 保持页面打开，等待朋友加入。

## 4. 手机 B 加入

1. 点 **加入房间**。
2. 输入手机 A 的 6 位数字。
3. 点 **连接房间**。
4. 页面自动交换 Offer / Answer。
5. 两边显示 **局域网直连成功** 后自动进入游戏。

## 5. 游戏同步验收

### A. 双玩家可见与移动

1. A 移动，B 必须能看到。
2. B 移动，A 必须能看到。
3. 两人同时移动至少 10 秒，不应长期卡死或持续漂移。

### B. 瞄准和射击

1. A 连续射击，B 能看到。
2. B 射击，A 能看到。
3. 怪物受击与死亡结果两边一致。

### C. 冲刺

1. A 测试冲刺。
2. B 测试冲刺。
3. 冷却期间不能无限重复冲刺。

### D. 独立生命、经验与升级

1. 让其中一人单独吃食物。
2. 两人的经验不能错误地一起增加。
3. 对应玩家升级三选一后，只应用到自己的角色。

### E. 敌人、环境与掉落

确认敌人追逐、碰撞扣血、食物掉落、珊瑚 / 水母 / 洋流没有长期分叉。

### F. Boss

确认两边同时看到鲨鱼 Boss，Boss 血量、蓄力、冲刺、受击、死亡和奖励一致。

### G. 本地 UI

中英切换、声音开关只影响本机表现，不应断开网络。

## 6. 通过标准

正式真机联机至少持续 **10 分钟**：

- 双方持续看到对方移动；
- 双方射击和冲刺都能被另一端看到；
- 敌人、食物、Boss、生命值没有持续性分叉；
- 无页面崩溃、永久冻结或持续不同步；
- 手机 UI 不被刘海 / Dynamic Island / 圆角遮挡关键按钮。

全部满足后才记录为 **PASS**。

## 7. 如果仍然连不上

1. 确认打开的是 `deep-sea-duo.netlify.app`，不是旧的 raw.githack 固定 commit 链接；
2. 确认底部是 `NET-N1`；
3. 创建房间后确认出现真实 6 位数字；
4. 两台手机确认在同一个 Wi‑Fi / 热点；
5. 关闭 VPN / 代理 / Private Relay 后再试；
6. 截下完整错误文字与 build 标识。

## 8. 高级手动模式

大厅底部仍保留：

**“高级备用：手动局域网连接”**

这是维护/故障排查用途，不是正常玩家流程。普通玩家只使用 6 位房间码。
