# 《深海搭档 / Deep Sea Duo》两台手机真实联机验收流程

当前正式联机方式已经改成 **6 位房间码自动配对**。正常玩家不再需要来回复制 WebRTC Offer / Answer 长文本。

## 0. 测试前准备

准备两台手机：

- **手机 A：房主（Host）**
- **手机 B：加入者（Guest）**

推荐：iPhone / iPad 用 Safari，Android 用 Chrome。两台手机都横屏。

## 1. 让两台手机处于同一个局域网

推荐顺序：

1. 两台手机连接同一个 Wi‑Fi；或
2. 手机 A 开个人热点，手机 B 连接 A 的热点。

如果使用 VPN、代理、iCloud Private Relay，联机测试时先关闭。若路由器开启 AP Isolation / Client Isolation，也可能阻止局域网设备互相连接。

## 2. 两台手机打开同一个 HTTPS 游戏地址

要求：

- 都是 `https://` 页面；
- 两台手机打开同一个版本；
- 发布新版本后，两边都刷新一次。

## 3. 手机 A 创建房间

在手机 A：

1. 点 **创建房间**。
2. 等待页面显示一个 **6 位数字房间码**，例如 `482731`。
3. 把这 6 位数字告诉朋友即可。
4. 手机 A 保持页面打开，等待手机 B 加入。

不需要复制任何长 JSON / SDP 文本。

## 4. 手机 B 加入房间

在手机 B：

1. 点 **加入房间**。
2. 输入手机 A 的 6 位数字。
3. 点 **连接房间**。
4. 页面会自动从信令服务获取房主 Offer、生成 Answer，并自动交回房主。
5. 两边出现“局域网直连成功”后，房间面板消失，游戏开始。

## 5. 这套联机的技术含义

Supabase 只做一次性的 **信令交换**，相当于帮两台手机自动传递 Offer / Answer。

真正进入游戏后：

- 房主仍然是唯一权威模拟；
- 移动、射击、怪物、掉落、Boss 等状态仍通过 WebRTC 点对点传输；
- 游戏不是由 Supabase 持续托管或模拟；
- 信令记录大约 10 分钟后自动过期，成功连接后也会主动清理。

## 6. 真机验收清单

### A. 双玩家可见与移动

1. A 移动，B 必须能看到。
2. B 移动，A 必须能看到。
3. 两人同时移动 10 秒，不应出现长期卡死或持续漂移。

### B. 瞄准和射击

1. A 在右侧拖动瞄准并连续射击，B 能看到。
2. B 射击，A 能看到。
3. 怪物受击与死亡结果两边一致。

### C. 冲刺

1. A 测试冲刺。
2. B 测试冲刺。
3. 冷却期间不能无限重复冲刺。

### D. 独立生命、经验与升级

1. 让其中一人单独吃食物。
2. 两人的经验不能错误地一起增加。
3. 对应玩家升级三选一后，只应用到自己的角色。

### E. 敌人、环境与掉落

确认：

- 敌人追逐结果一致；
- 碰撞扣血一致；
- 食物掉落位置一致；
- 珊瑚、水母、洋流表现没有长期分叉。

### F. Boss

确认：

- 两边同时看到鲨鱼 Boss；
- Boss 血量一致；
- 蓄力、冲刺、受击、死亡一致；
- Boss 奖励掉落一致。

### G. 本地 UI

中英切换、声音开关只影响本机表现，不应断开网络。

## 7. 通过标准

正式真机联机至少持续 **10 分钟**：

- 双方持续看到对方移动；
- 双方射击、冲刺都能被另一端看见；
- 敌人、食物、Boss、生命值没有持续性分叉；
- 10 分钟内无页面崩溃、永久冻结或持续不同步；
- 手机 UI 不被刘海 / Dynamic Island / 圆角遮挡关键按钮。

全部满足后记录为 **PASS**。

## 8. 6 位房间码连不上时

按顺序检查：

1. 两台手机确认在同一个 Wi‑Fi / 热点。
2. 两台手机都确认可以访问互联网，因为自动交换 Offer / Answer 需要短暂访问 Supabase 信令服务。
3. 确认输入的是完整 6 位数字。
4. 房间码超过约 10 分钟后会过期，让房主返回大厅重新创建。
5. 两边刷新页面，再创建一个新的房间码。
6. 关闭 VPN / 代理 / Private Relay。
7. 同一个 Wi‑Fi 仍失败，检查路由器客户端隔离。
8. 热点失败但普通 Wi‑Fi 成功，通常是热点系统限制。

## 9. 完全没有互联网时

大厅底部有折叠项：

**“高级备用：无网时手动连接”**

只有在两台手机仍处于同一局域网、但无法访问 Supabase 信令服务时才使用。它保留原始 Offer → Answer 手动交换能力，作为故障兜底，不是正常玩家流程。

## 技术边界

当前 WebRTC 使用 `RTCPeerConnection({ iceServers: [] })`，目标仍然是同一局域网 / 热点直连。6 位房间码解决的是“自动交换连接信息”，不是公网 TURN 中继，因此跨运营商 NAT / 任意公网直连不属于当前 V1 保证范围。
