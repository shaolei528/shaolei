# 《深海搭档 / Deep Sea Duo》两台手机真实联机验收流程

这份流程专门给第一次测试 WebRTC 联机的人。游戏没有公共游戏服务器：两台手机先打开同一个 HTTPS 游戏页面，再通过一次性的 **房主连接码（Offer）→ 加入者应答码（Answer）→ 房主确认** 建立局域网直连。

## 0. 测试前准备

准备两台手机，下面称为：

- **手机 A：房主（Host）**
- **手机 B：加入者（Guest）**

推荐浏览器：

- iPhone / iPad：Safari 最新版。
- Android：Chrome 最新版。

两台手机都把屏幕转成 **横屏**。第一次触摸页面后浏览器才允许游戏声音播放，这是正常的手机浏览器限制。

## 1. 让两台手机处于同一个局域网

二选一即可。

### 方法 A：同一个 Wi‑Fi（最推荐）

1. 手机 A 和手机 B 都连接同一个家用 Wi‑Fi。
2. 临时关闭两台手机的 VPN、代理、iCloud Private Relay 一类可能改变网络路径的功能。
3. 如果路由器有“AP Isolation / Client Isolation / 客户端隔离”，必须关闭，否则同一个 Wi‑Fi 下的设备也可能互相看不到。

### 方法 B：手机热点

1. 手机 A 开启个人热点。
2. 手机 B 连接手机 A 的热点。
3. 手机 A 自己继续保持热点开启。
4. 两台手机分别用浏览器打开游戏页面。

> 某些手机系统会隔离热点客户端。如果热点方式始终无法建立直连，先换成“方法 A：同一个 Wi‑Fi”判断是不是热点系统限制。

## 2. 两台手机打开同一个游戏网址

Pages 发布成功以后，两台手机都打开项目的 GitHub Pages 游戏网址。

要求：

- 必须是 `https://` 页面。
- 两台手机必须打开同一个版本。
- 不要一台打开本地旧缓存、一台打开刚更新的新版本。

如果刚发布了新版本，建议两台手机都刷新一次页面再开始。

## 3. 手机 A 创建房间

在 **手机 A**：

1. 点击 **“创建房间”**。
2. 等待文本框里出现一大段连接码。
3. 这段就是 **房主连接码 / Offer**。
4. 全选并复制整段内容，不要只复制一部分。
5. 把它传给手机 B。

传码方式随意，只要不改内容即可，例如聊天软件、AirDrop、Nearby Share、共享备忘录等。

## 4. 手机 B 生成应答码

在 **手机 B**：

1. 点击 **“加入房间”**。
2. 把手机 A 的整段 Offer 粘贴到文本框。
3. 点击 **“生成我的应答码”**。
4. 等待文本框变成另一大段连接码。
5. 这段就是 **加入者应答码 / Answer**。
6. 全选、复制整段 Answer，再传回手机 A。

如果提示“局域网连接信息生成超时”，先确认两台手机仍在同一个 Wi‑Fi / 热点，然后重新刷新两边页面，从第 3 步重新生成，不要继续使用上一次的旧码。

## 5. 手机 A 完成连接

回到 **手机 A**：

1. 把文本框里原来的 Offer 全部删掉。
2. 粘贴手机 B 发回来的完整 Answer。
3. 点击 **“粘贴朋友应答码后确认”**。
4. 等待几秒。

成功时：

- 两边的房间面板都会进入直连状态并让游戏开始。
- 手机 A 是权威主机，负责真正运行敌人、伤害、掉落、Boss 和世界状态。
- 手机 B 发送自己的操作，并显示手机 A 广播回来的真实游戏状态。

## 6. 真机验收清单

建立连接以后，按顺序测试。每一项都应该在 **两台手机上同时看到一致结果**。

### A. 双玩家可见与移动

1. 手机 A 左侧滑动，让蓝绿色角色移动。
2. 手机 B 应看到手机 A 的角色移动。
3. 手机 B 左侧滑动，让紫色搭档移动。
4. 手机 A 应看到手机 B 的角色移动。
5. 两人同时移动 10 秒，确认没有一方长期卡死或一直漂移。

### B. 瞄准和射击

1. 手机 A 在屏幕右侧按住拖动，连续发射水弹。
2. 手机 B 应看到同样的水弹轨迹和怪物受击。
3. 再由手机 B 连续射击，手机 A 也必须看到。

### C. 冲刺

1. 手机 A 移动时点击右下角 **“冲刺”**。
2. 两边都应看到冲刺位移和拖尾。
3. 手机 B 再测试一次。
4. 冷却期间连续点击不应无限冲刺。

### D. 独立生命、经验与升级

1. 让其中一位玩家吃掉食物，另一位先不要吃。
2. 确认两人的经验不是绑在一起增长。
3. 升级出现三选一时，由对应玩家选择强化。
4. 选择完成后，另一位玩家不能被错误地自动应用同一个升级。

### E. 敌人、环境和掉落

1. 让普通敌人追逐两位玩家。
2. 确认碰撞扣血结果在两边一致。
3. 击杀敌人，确认掉落食物的位置在两边一致。
4. 靠近珊瑚、水母和洋流，确认环境表现与碰撞没有明显分叉。

### F. Boss

正常游玩直到鲨鱼 Boss 出现，或在开发调试时缩短 Boss 时间后测试：

1. 两边必须同时看到 Boss。
2. Boss 血量条必须同步。
3. Boss 蓄力、冲刺、受击和死亡结果必须一致。
4. Boss 死亡后的高价值食物掉落位置必须一致。

### G. 中英切换与声音

1. 任意一台点击右上角 **EN / 中文**。
2. 这只是本机界面语言，不应该改变网络状态。
3. 点击声音开关，确认该手机能独立静音/恢复声音。
4. 射击、冲刺、受伤和 Boss 阶段应有不同声音反馈。

## 7. 通过标准

一次正式真机联机测试至少持续 **10 分钟**，并满足：

- 双方都能持续看到对方移动。
- 双方射击、冲刺都能被另一端看见。
- 敌人、食物、Boss、生命值没有持续性分叉。
- 手机 B 不会自己生成一套与房主不同的世界。
- 横屏 UI 没有被刘海 / Dynamic Island / 圆角遮住关键按钮。
- 10 分钟内无页面崩溃、无明显持续掉帧、无连接后永久卡死。

全部满足后，记录为 **PASS**。

## 8. 连不上时按这个顺序排查

1. 确认两台手机是同一个 Wi‑Fi，或者 B 确实连接了 A 的热点。
2. 关闭 VPN / 代理 / Private Relay 后重试。
3. 两边刷新页面，重新生成一整套新的 Offer / Answer；旧码不要复用。
4. 检查复制的 JSON 是否完整，开头通常是 `{`，结尾是 `}`。
5. 同一个 Wi‑Fi 仍失败：检查路由器是否开启客户端隔离。
6. 热点失败但 Wi‑Fi 成功：通常是手机热点系统的隔离限制，不是游戏规则层 bug。
7. 一端进入游戏但另一端一直不动：重新连接并确认双方版本完全一致。
8. 如果只有声音没有播放：先触摸一次页面，这是移动浏览器的自动播放限制，不影响联机。

## 技术说明

当前 WebRTC 使用 `RTCPeerConnection({ iceServers: [] })`，只收集本地 ICE 候选，不依赖 STUN/TURN，也没有公共游戏中继服务器。因此它的目标就是同一局域网 / 热点里的直连；跨公网、运营商 NAT 或强隔离网络不属于当前 V1 的保证范围。
