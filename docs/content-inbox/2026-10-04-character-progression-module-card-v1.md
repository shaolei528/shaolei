# Character & Progression — 独立模块任务卡 V1

**状态：DRAFT / NOT IMPLEMENTED / 供后续 AI 领取与用户审阅**  
**本卡目的：**给未来负责“玩家角色与个人成长”的 AI 一个清楚范围，使其能独立工作，不把角色、生命值、背包、战斗、任务 UI 和存档全写进同一套逻辑。  
**证据快照：**2026-10-04，分支 `fix/awakening-production-gate-qa-findings-v1`，HEAD `54d294abc13dd19ee53b56563fe43aaecc81b9ba`。工作区有来源未确认的并行改动；本卡不归属或覆盖它们。

**当前目标更新：**用户认可隔离 3/4 原型的玩法/镜头方向，但画质仍不合格；目标是让 successor 承接真实游戏，V21 在 successor 通过画面、玩法与兼容验收后逐步退役。本卡中的 V21 资料只是旧系统基线；未来实现应面向经核实的 successor 状态/API，不要把成长功能继续堆进旧页面作为长期方案。

## 1. 玩家要获得什么

玩家应能看懂“我是谁、我现在状态如何、我这趟冒险带来了什么成长、下一趟能做什么选择”。角色成长应让玩家为探索和合作逐渐形成自己的玩法风格，而不是单纯堆数值、刷经验条，或让角色面板成为另一份互相矛盾的游戏状态。

长期主循环仍是 HOME 准备 → OUTSIDE 探索/战斗/搜集 → 带回收获 → HOME 成长。角色成长是这条循环的支撑模块，不应替代 NPC、任务、物品、战斗或生存系统。

## 2. 五款参考游戏在本模块中的原创转化

- **Crashlands：**成长获得时要有立即、易懂的反馈；新能力应解决玩家实际遇到的问题。
- **Terraria：**成长可以逐步打开新的地点/应对方式，但每道门槛都要说明原因；门槛事实由世界/任务模块拥有。
- **Minecraft：**玩家身份和外观应能表达个性；外观选择不能偷偷改变战斗能力。
- **Don't Starve Together：**成长选择可以帮助玩家准备远征，但风险必须清楚，不能用隐藏惩罚逼玩家选固定流派。
- **Stardew Valley：**成长可连接居民和 HOME 社区贡献，让回家也有意义；关系和居民请求归 NPC/任务模块。

只吸收体验，不复制原作的职业、技能树、人物外观、数值、名称或 progression 系统。

## 3. 当前实现核对：有生存状态，还没有核实到升级系统

**VERIFIED（源码快照）：**

- `modules/core/runtime-state.js` 定义玩家的临时会话 ID、名称、颜色、坐标、HP、饥饿、理智，以及独立的 `inventory` 对象。
- `saveLocal()` 使用 `abyssal_wake_save_v5`，保存名称、位置、HP、饥饿、理智、背包及 `hasLeftCamp`；同文件读取 v4 迁移数据。
- `modules/survival/status.js` 负责更新 HP、饥饿和理智。角色面板若展示这些数值，应读取 Survival owner 的当前值，不建立副本。
- `modules/ui/base-ui.js` 展示生命/饥饿/理智与目标提示；UI 是展示层，不是角色成长权威。
- `modules/input/interaction-v12.js` 提供背包/交互 UI 扩展。显示装备/物品时应读取 Inventory owner。
- `survival-v21.html` 是当前模块顺序和功能是否进入 V21 的核对入口；新增系统不能只创建文件就算接入。

**VERIFIED（有限范围源码搜索）：**在当前 V21 活动代码中没有找到明确的经验值、等级成长或技能解锁 owner/API。概念图里展示的“Lv.1”和 Character 页签是视觉/功能参考，不能当成现成功能。搜索未覆盖所有动态生成、浏览器扩展或未来未提交代码；新会话必须复核。

**边界结论：**当前角色基础状态是 ACTIVE/PARTIAL；可玩的角色等级、经验、技能点、属性构筑、外观选择系统均标 **PLANNED / 未核实实现**。当前 v5 存档结构脆弱且有别的改动，不能直接在本卡中擅自扩字段或改迁移。

## 4. 模块 ownership：数据不重复

**唯一主责：Character & Progression。**长期规划中，它拥有玩家主动选择的角色身份偏好，以及未来个人成长记录/解锁选择。它只接收由领域 owner 确认的成长事件，不能自己判定玩家击杀、发现 POI、拿到物品或完成任务。

| 状态/行为 | 唯一 owner | Character & Progression 可以怎样使用 |
|---|---|---|
| 名称、当前运行时玩家快照 | Core State / 当前 V21 runtime | 只读；本卡不改变会话 ID 或跨设备身份语义 |
| HP、饥饿、理智、死亡与恢复 | Survival | 只读角色面板；任何新属性影响这些规则须单独审阅 Survival 接口 |
| 背包、装备、资源数量 | Items / Inventory | 展示快照或提交请求；不能直接改 `inventory` |
| 攻击与已接受伤害 | Combat & Weapons | 只消费已确认伤害/战斗事件，不判定怪物生命归零 |
| 怪物生命与 defeat 事件 | Creatures & AI | 消费一次确认的 defeated 事件，不以本模块推断击杀 |
| POI 发现、地区开放 | POI & Exploration | 接收已确认的发现/解锁信息；不自行改变地图和碰撞 |
| 目标、剧情条件、任务完成 | Quest & Narrative | 可消费已确认阶段事实；不自建第二套任务完成标记 |
| 玩家展示与设备交互 | UI & Map / Input & Accessibility | 提供只读角色快照和标准化选择请求；不决定等级、技能或状态 |
| 存档序列化、迁移、持久范围 | Core Save / persistence coordinator | 未来提供版本化资料片段；不能由每个角色功能各自写 localStorage |
| Relay 传输与共享世界语义 | Network & Co-op + 对应世界 owner | 不改 Relay 消息；个人成长与共享进展先分开定义 |

上表是**目标职责**，不表示这些接口现已存在。未来 AI 要先查 V21 启动顺序和可用 API，再设计可兼容的小接口。

## 5. 拆分成可独立交付的阶段

### Character-0：只读角色数据与显示合同（本卡推荐的首个工程切片）

梳理当前来源，定义角色页只显示哪些真实字段、字段由谁提供、空值/加载失败时如何显示。只准备可视化草图或静态 UI 方案，不创建等级/经验，不改存档。目的在于先让玩家看懂当前角色，而不是假装已经有成长系统。

### Character-1：successor 的只读角色面板（独立选择后）

在 successor UI 里展示名称和实际存在的生存/背包摘要；全部通过当前 owner 读取。若素材比例或画质不达标，使用 A+1 按已对齐合同制作的隔离高质量像素风候选，不覆盖正式角色图集。检查真实 successor 画面、文字尺寸、桌面与手机布局后才算体验验收。

### Character-2：个人成长规则设计（先做 DRAFT）

提出一条有明确作用的小成长路线，例如安全返家/新地点发现后获得一次远征准备选择。每个里程碑只能由对应模块发出确认事件；说明是否个人或团队共享、失败/重复事件是否发奖，以及它如何帮助下一趟出行。玩家确认玩法后才形成实现任务。

### Character-3：选择与效果原型（单独实现任务）

一次只实现一个 milestone 与一个有取舍的成长选择，明确正反例、上限、回退和影响的模块。不要同时加入 XP 曲线、职业、天赋树、装备词缀、任务链和多人共享解锁。

### Character-4：持久化/多人合同（单独架构任务）

先决定成长记录属于玩家、角色还是共同世界，确定离线、刷新、断线、换设备和多人同时解锁时的行为，再设计 save migration/authority。除非有明确的可回退实施范围，保持现有 v5 save 与 Relay 不变。

## 6. 高品质角色美术与表现要求

- 角色设计采用原创的现代沿海幸存者造型：轮廓清楚、装备有用途感、面部和姿态能传达状态；HOME 用较温暖的人性色彩，OUTSIDE 逐步增加冷色与异常线索。
- 目标为 Modern High-Detail Pixel Art。细节要在实际游戏尺寸读得出，像素簇有意组织；不能用柔焦/抗锯齿或随意缩放制造“高清”假象，也不能放大成粗糙马赛克。
- 当前 sprite sheet 的真实格子、动画方向和 V21 绘制比例必须开工时重新查验。新的肖像、行走、攻击、受伤动画分别有各自的尺寸/帧/透明度合同；不能把 24×32 单帧合同套给所有新图，也不能未经测试改变 renderer 合同。
- 状态动画只表现已经发生的状态。眨眼、发光、受伤闪烁、技能特效和升级音效都不能改 HP、伤害、掉落、碰撞或保存状态。
- 验收至少比较原图、最近邻放大图、实际游戏 1×尺寸；验证 HOME 与 OUTSIDE 对比、角色/地面/道具比例、帧间可读性和桌面/手机文字布局。缺真实画面证据时标 UNKNOWN / BLOCKED，不算美术通过。
- 另一个 AI 当前专注 SafeCamp 地表候选时，角色模块应只提交独立的角色说明/候选目录，不能同时改它的图集脚本、素材或预览清单。

## 8. 本卡验收条件

1. 新 AI 能从本卡判断角色状态哪些已有、哪些只是计划，不把概念图 UI 当运行事实。
2. 每种数据都有一个 owner，面板、成长记录和存档不各自维护重复值。
3. 首次交付是一个小模块切片，不同时开发全套角色构筑和联机存档。
4. 高质量像素角色经过实际游戏比例、缩放、动画和设备尺寸检查；不能验收时明确保留 REVISE/UNKNOWN。
5. 有针对当前目标的测试和一项相邻系统回归证据；真实游玩未执行就不宣称完整体验通过。

本卡只是模块规划，不创建角色升级功能、不生成正式美术，也不授权修改/迁移 save、联网协议或 production 资源。
