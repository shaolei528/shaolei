## Key answer: why 64×32 appears

`prototypes/successor-3-4/successor-renderer.js:21-35` takes a **64×64 source crop** from `assets/art-v21/terrain-v21.png` and clips/scales it to a **64×32 screen diamond**. Thus 64×32 is the terrain's base-zoom screen footprint in the successor, not its source PNG cell size. The atlas is 320×256, arranged 5×4 64×64 cells (`assets/art-v21/manifest.json:4-7`; V21 API `terrain-v21.js:16`). `64×64` is also the V21/awakening world-grid cell (`ART_BIBLE.md:10-11`; `AWAKENING_ASSET_CONTRACT.md:8-13`). These are separate units. The visible tile stays a crop of legacy art; nearest-neighbor rendering prevents blur but cannot create missing detail.

Other small values are likewise frequently source **frame/cell** sizes, not whole sheet sizes. The four loaded sheets currently measure player 96×128, monsters 128×96, props 192×96, resources 128×32. Fixed crop contracts are respectively 24×32, 32×32, 48×48, 32×32. Successor draws them at 28×38, 38×38, variable 48×48×placement-scale, and 28×28 (`modules/core/runtime-state.js:3`; `prototypes/successor-3-4/successor-renderer.js:40-43`; `modules/render/base-renderer.js:2,6,8-10`).

### Asset adapter contract actually present

The experimental Awakening Art adapter normalizes individual manifest assets and sheet entries to source rectangles (`modules/render/awakening-art-assets-v1.js:38-48`), draws nearest-neighbor, defaults prop anchors to bottom-center, and supports frame strips using `frames`/`frameDurationMs` (`:58-74`). It loads `manifest.json` in normal mode or `manifest.preview.json` only in preview mode, with fallback on fetch/manifest/image failures (`:4-6,76-95`). Its terrain method currently hardcodes 64×64 display with top-left anchor (`:71`), a direct mismatch to the successor's 64×32 terrain-diamond display. This adapter does not prove those resources are the successor's active resources.
