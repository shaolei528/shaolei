# 今日 UI 候选：Safe Camp 出发准备板

**状态：DRAFT / NOT IMPLEMENTED**  
**请用户决定：keep / edit / discard**

## 玩家能得到什么

在 Safe Camp 的地图/任务面板里，用一张紧凑的“出发准备板”回答三个问题：为什么现在值得出发、目前还缺什么准备、带回目标物后能推进什么。玩家不必从长段任务文字里猜下一步，也不会把未发现的地点或未知威胁误当成已知事实。

## 一条示例信息

- **出发理由：** 调查 MIRE MART 停电后留下的异常痕迹。（当前远征目标文字）
- **风险情报：** 目前没有权威危险情报；怪物数量与具体位置未知。
- **准备情况：** 骨刃已制作；食物现有 2 份（是否足够由玩家决定）。
- **带回目标：** 2 个异质碎片；返家后可解锁野外装备架升级。

以上是 UI 布局样例。只有已经由游戏权威状态确认的内容才能显示为“已知”；未知内容要明确标成未知。示例地点缘由对应 `modules/world/awakening-expedition-loop-v1.js` 当前任务文字，不代表存在独立的 POI 发现记录；危害预告服务尚未确认。

## 模块交接

- **主责模块：** UI & Map。
- **配合模块：** POI & Exploration 提供地点和远征阶段；Quest & Narrative 提供叙事缘由；Items & Inventory、Survival & Needs 提供装备/物资/生存状态；Content & Localization 提供中文文案。
- **建议接口：** UI 读取一个只读的 `DepartureBriefSnapshot`（地点 ID、已确认理由、已知风险、未知项、准备需求与当前数量、返家收益 ID、更新时间），发送 `openMap` 或 `setWaypoint` 意图。所有阶段、需求、奖励资格仍由领域模块判定。
- **边界：** 面板不创建奖励、不消耗材料、不发现 POI、不预测没有数据支持的威胁，也不把静态地图演示数据当成实时世界。
- **建议文件范围（未来实现时）：** 新的 successor UI 外壳/面板文件；由 Integration & QA 单独检查 successor 入口装载和模块化边界。不得在该 UI 任务里删除 V7/V21、改存档或 Relay 协议、改生产素材清单。

## 美术方向与风险

- 3/4 场景保持完整可见；面板作为克制的海岸值班板/无线电记录卡，不使用 QA 控件或密集英文缩写。
- 高对比短行、清晰图标与文字标签同时表达状态；颜色不能作为唯一提示。手机上折叠为一张不遮角色和交互目标的卡片。
- **主要风险：** 当前 successor 没有完整的“已知风险/地点发现”只读服务；若没有可靠数据就隐藏对应字段并显示“尚无情报”，不能由 UI 编造。

## 验收办法

1. 桌面 1280×720 与窄屏 390×844 检查卡片尺寸、场景遮挡、文字可读性与触控目标；真实手机触控另列 UNKNOWN，直到实机检查。
2. 对照领域快照，核对地点、阶段、库存、需求和返家收益；未确认的威胁必须仍显示为未知。
3. 点击地图/设路标只发送输入意图；模拟延迟、拒绝和离线时，UI 不可提前修改任务阶段、库存或奖励。
4. 与 V21 暂存入口及正式 successor 外壳分别检查，明确 DEV / NOT PRODUCTION；此候选通过设计审查也不等于已实现或发布。
